# Verification Without Sufficiency

Code, data splits and per-question traces for *Verification Without Sufficiency:
Per-Chunk Filtering Fails on Multi-Hop RAG, and Decomposition Repairs It*.

[paper (PDF)](paper/final_paper.pdf) · [arXiv](https://arxiv.org/abs/XXXX.XXXXX)

## What this is about

A common way to reduce hallucination in RAG is to score each retrieved chunk and
drop the ones that fail. We measured how well three such signals separate gold
evidence from hard distractors, and found that all of them work on single-hop
questions and none work on multi-hop ones.

The cause is an assumption inside per-chunk scoring: that one chunk is a
sufficient premise for the answer. Multi-hop questions are built so that none is,
and the paragraph carrying the answer is the one the question does not name.

| | HotpotQA | 2Wiki | MuSiQue | SQuAD (1-hop) |
|---|---|---|---|---|
| entailment AUC | 0.643 | 0.523 | 0.560 | **0.951** |

End to end, per-chunk gating is significantly worse than not filtering at all on
all three multi-hop datasets, across three generator sizes and two prompts.

Conditioning the hypothesis on the **decomposed sub-question** instead of the
original query lifts entailment on a later hop from 0.546, which is chance, to
0.779 (paired bootstrap +0.232, [0.210, 0.255]). Hop count then stops mattering.

## Reproducing

Every table and figure is generated by a script reading `results/analysis/*.csv`.
No number in the paper was typed by hand.

```bash
pip install -r requirements.lock
python tests/test_core.py            # 18 checks, no GPU, ~10 seconds
```

Full pipeline in [REPRODUCE.md](REPRODUCE.md). Total cost was about $22 of
Modal compute and four and a half hours of wall clock.

## Layout

| Path | What |
|---|---|
| `src/triver_core.py` | the three signals, HRR algebra, metrics, statistics |
| `modal/` | one file per experiment stage, run with `modal run` |
| `splits/` | the exact question IDs, fixed seed 1337 |
| `results/analysis/` | every aggregate a table or figure reads |
| `results/tex/` | generated LaTeX table fragments |
| `traces/` | per-question JSONL for every configuration |

## Negative results included

The paper reports what did not work as carefully as what did:

- Holographic Reduced Representation matching is at chance (0.62 AUC) and we
  give the extraction dilemma that explains it.
- Our own conditional selector recovers gold recall but is significantly *worse*
  than no filtering on MuSiQue. We report that.
- An earlier version of this work evaluated on ten questions and reported 30-40%
  Exact Match at 0.5B. The 500-question measurement puts the true value near
  10%. See `PREREGISTRATION.md` for how we avoided repeating that.
